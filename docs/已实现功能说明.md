## 一、`ppt_course`（`ppt-course-mvp` 包）

面向：将文字偏多的 `.pptx` 转为更偏「录课稿」的版式；提供 **命令行** 与 **本机 Web** 两种使用方式。

### 1.1 命令行

| 能力 | 说明 |
|------|------|
| `ppt-course transform` | 输入一份 `.pptx`，输出同目录下 `原文件名_course.pptx`（可用 `-o` 指定输出路径） |
| `ppt-course transform --plan-json` | 可选：将规划结果写出为 JSON 文件，便于排错或对接外部流程 |
| `ppt-course serve` | 启动 FastAPI + 静态前端（默认 `127.0.0.1:8765`，支持 `--host`、`--port`、`--reload`） |
| `ppt-course --version` | 打印包版本号 |

入口：`python -m ppt_course` 与 `ppt-course` 等价。

### 1.2 核心流水线（与 CLI / Web 共用）

| 环节 | 已实现行为 |
|------|------------|
| 读取 | 使用 `python-pptx` 打开 `.pptx`，逐页遍历形状（含组合图形内的文本） |
| 结构化抽取 | **启发式**：按关键词与规则将文本归为规则 / 案例 / 处罚 / 互动 / 小结 / 叙述等类型（见 `BlockKind`），非 LLM |
| 页面规划 | 按固定区块顺序聚合，超长内容按字数拆成「续页」 |
| 生成新版式 | 空白版式 + 标题区 + 分区正文文本框；可为备注页写入原始页摘录（便于口播参考） |
| 输出 | 写入新的 `.pptx` 文件 |

### 1.3 Web 服务（`ppt_course/web/app.py`）

依赖：`FastAPI`、`uvicorn`、`python-multipart`（随根目录 `pyproject.toml` 安装）。

#### HTTP 接口

| 路径 | 方法 | 说明 |
|------|------|------|
| `/` | GET | 返回单页工作台前端（`static/index.html`） |
| `/assets/*` | GET | 静态资源（CSS / JS） |
| `/api/health` | GET | 健康检查，返回 `{"status":"ok"}` |
| `/api/parse` | POST | `multipart` 上传 `.pptx`，返回 JSON：文件名、页数、每页文本结构（标题、全文、`text_blocks`、备注、版式名、形状内图片数/表格数等）；可选生成预览会话；成功时在服务端**持久化**本次解析（见下），响应含可选字段 `task_id` |
| `/api/tasks` | GET | 已持久化解析任务的**摘要列表**（文件名、页数、创建时间、是否有预览图等） |
| `/api/tasks/{task_id}` | GET | 指定任务的完整解析 JSON（结构与解析接口正文一致，含 `slides` 全文） |
| `/api/tasks/{task_id}/preview/{slide_index}` | GET | 该任务已保存的第 `slide_index` 页 **PNG**（与临时会话 `/api/preview/...` 并存） |
| `/api/tasks/{task_id}` | DELETE | 删除该任务的本地目录（不可恢复） |
| `/api/preview/{session_id}/{slide_index}` | GET | 若预览会话存在且索引合法，返回对应页的 **PNG**（`image/png`） |
| `/api/transform` | POST | 上传 `.pptx`，返回课程化后的 **完整 `.pptx` 二进制**；响应头含 `X-Source-Slides`、`X-Output-Slides` |
| `/docs` | GET | FastAPI 自动生成的 OpenAPI 文档页面 |

上传体积上限：**单文件 50MB**（与 `transform` 一致）。

#### 浏览器端界面（`ppt_course/static/`）

| 能力 | 说明 |
|------|------|
| 上传 | 选择或拖放 `.pptx` |
| 已存任务 | 上传区下方列出本机已持久化的解析记录；点击条目**弹出对话框**查看该次解析的幻灯片列表与图文预览（接口 `/api/tasks/...`）；支持刷新列表、单项删除 |
| 解析后布局 | 左侧为幻灯片列表；右侧为当前页：优先展示整页 **PNG 预览**（见下）+ 下方文本解析与演讲者备注 |
| 整页缩略图 / 大图 | 当服务端成功生成 PNG 时，列表缩略图与主预览区使用 `/api/preview/...` 拉取图片；未生成时列表为数字占位，右侧仅文本 |
| 生成课程化 | 使用「生成课程化 PPTX」按钮，再次上传当前文件并下载结果（与命令行 `transform` 同一套流水线） |
| 更换文件 | 回到上传区，可换另一份 `.pptx` 重新解析 |

#### 整页 PNG 预览（可选能力）

- **条件**：运行 Web 服务的机器已安装并可调用 **LibreOffice（`soffice`）** 与 **Poppler（`pdftoppm`）**。  
- **过程**：`PPTX → PDF（LibreOffice）→ 逐页 PNG（pdftoppm）`，文件落在临时目录；通过 `session_id` 绑定会话。  
- **会话**：内存中登记预览会话，临时目录超出数量上限（约 30 个会话规模）时淘汰较早会话并删除目录。  
- **限制**：刷新浏览器后需重新上传；**不是**公网 CDN，仅为同源临时 URL。

### 1.4 解析结果本地持久化（可选目录）

| 项 | 说明 |
|----|------|
| 触发时机 | 每次 `/api/parse` **解析成功**（含仅有文本、无 PNG 的情形）后写入磁盘 |
| 默认目录 | 仓库根目录 **`ppt_course_data/tasks/{uuid}/`**（内含 `meta.json`（解析全文）、`source.pptx`、`previews/slide-*.png`（若有））；旧版曾为 `ppt_course/user_data/`，若仍在使用环境变量 `PPT_COURSE_DATA` 则以该路径为准 |
| 环境变量 | `PPT_COURSE_DATA`：指定数据根目录（绝对或相对路径均可），任务位于其下 `tasks/` |
| 容量 | 任务数超过 **200** 条时自动删除**最旧**目录 |

### 1.5 配置与工程

| 项 | 说明 |
|----|------|
| Python 版本 | `>=3.9`（`pyproject.toml`） |
| 静态文件打包 | `ppt_course/static/` 通过 `setuptools` `package-data` 打入 wheel |

## 二、`ppt_course_rebuilder/`（独立 CLI 子项目）

与根目录 `ppt_course` **并存**，单独目录、单独 `requirements.txt` 与 `main.py`，**不依赖根目录包的 Web**。

### 2.1 运行形态

| 能力 | 说明 |
|------|------|
| `python main.py --mode analyze` | 读取 `--input` 指定 `.pptx`，写出 `output/slide_analysis.json` |
| `python main.py --mode plan` | 读取已有 `slide_analysis.json`，经 AI 规划后写出 `output/course_slides.json`；无密钥或失败时用本地兜底规划 |
| `python main.py --mode build` | 读取 `--course-slides`（默认 `output/course_slides.json`），生成 `--output` 指定 `.pptx` 与 `output/page_scripts.md` |
| `python main.py --mode full` | 串联 analyze → plan → build；可选 `--export-images` 尝试用本机 LibreOffice 导出 PNG 到 `output/exported_images/` |
| 环境变量 | `.env`：`AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL`（见 `.env.example`） |
| 无 AI 时试跑模板 | 可使用 `output/sample_course_slides.json` 跑 `build`，验证版式与生成 |

### 2.2 已实现模块要点

| 模块 | 作用 |
|------|------|
| `src/ppt_reader.py` | 读取每页标题、文本块、图/表计数、备注、版式名等 |
| `src/models.py` | `RawSlide`、`SlideAnalysis`、`CourseSlide` 等 Pydantic 模型；课程页含 `source_slide_indexes`；预留 `image_prompt` / `image_url` / `asset_urls` 字段 |
| `src/ai_client.py` | OpenAI 兼容 Chat Completions，`response_format` JSON，失败重试一次 |
| `src/slide_analyzer.py` | 按 Prompt 输出单页 `SlideAnalysis`；失败时用本地兜底分析 |
| `src/course_planner.py` | 将多页分析合并为 `CourseSlide` 列表；失败时用保守「每页一张 rule_card」兜底 |
| `src/template_engine.py` + `templates/theme.py` | 按 `CourseSlide.type` 渲染 title / agenda / transition / rule_card / case_dialogue / quiz / explanation / summary；本地 `templates/assets/` 占位图标（缺失时可由代码生成） |
| `src/ppt_writer.py` | 汇总生成 `.pptx`，单页失败时插入错误提示页并继续 |
| `src/image_exporter.py` | 可选：检测 `soffice`/`libreoffice` 将 `.pptx` 转 PNG |
| `main.py` | 写出 `output/summary_report.json`；统一错误与警告收集 |

子项目自带 **`README.md`**（安装、命令、产物路径），与本文档互补。

## 文档修订记录

### 编排规则（请先读）

- **日期是大分类**：每一档独立的日历日以三级标题 **`### YYYY-MM-DD（中文日期）`** 表示；**多个日期之间**：较新的日期写在**上面**，较早的日期写在**下面**。  
- **同一天内可能有多轮迭代**：在同一日期标题下，用四级标题 **`#### 迭代 n`** 区分（`n` 可取 1、2、3…，**数值越大表示当日越晚、越新**）；**同一天内**，较新的迭代写在**上面**，较早的迭代依次往下（即从**上到下 = 从新到旧**）。  
- 若当日最新一轮需要醒目，可在标题后缀 **`（本日最新）`**。
