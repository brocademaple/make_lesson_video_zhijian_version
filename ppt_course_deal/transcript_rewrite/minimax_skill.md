# MiniMax T2A 口播改写规范（内置技能）

在向大模型请求「口播稿优化」时，本文件完整置于 **user** 消息；**system** 仅为极简角色说明。合法插入语以 **[MiniMax T2A 支持的插入语]** 列表为准（须与仓库 `minimax_t2a_allowlist.json` 一致；若有出入以 JSON + 下游 sanitize 为准）。

【输出格式（必须遵守）】

1. **先**输出改写后的口播**正文**（可直接送去 T2A 朗读的一段连续文本；不要包在代码块里）。
2. 正文结束后**单独一行**写：`---`（三个英文减号），再换行。
3. **最后**输出一个 **Markdown JSON 代码块**（首行须为 ` ```json `），内含 **MiniMax 合成参数建议**（见下节字段说明）。该 JSON 块内可含 `delivery_notes`（一两句中文，说明为何如此设参，便于人类复核）。
4. **不要**在正文与上述 JSON 之外再写前言、标题、总结段落或重复本规范。

【MiniMax 合成参数建议（JSON 字段）】

下列字段**均为可选**；只填你认为相对服务端 / 用户当前默认需要调整、且能从文本特征 justify 的项。**数值须在官方 T2A 许可范围内**（与 Web「音频生成参数」一致：`speed` 约 0.5–2，`vol` 约 0.1–10，`pitch` 约 -12–12）。情绪 **`emotion`** 只能取下列之一（与控制台一致）：`happy`、`calm`、`fluent`、`whisper`、`sad`；不确定时可**省略**该字段（表示沿用界面「自动」）。

JSON 示例（字段说明见下一节「如何根据文本特点选参」）：

```json
{
  "speed": 1.05,
  "vol": 1.0,
  "pitch": 0,
  "emotion": "calm",
  "delivery_notes": "本节概念密度高，略放慢、平静讲解便于跟听。"
}
```

【如何根据文本特点选参】

面向**需要抓住注意力**的在线培训课程，整体目标是：**听起来像在讲课，而不是念说明书**。请结合 **【待优化原文】** 的实际语气与结构做判断（以下为启发式，不是死板规则）：

| 文本特点 | 语气与节奏意图 | 可参考的参数方向 |
|----------|----------------|------------------|
| 开场、案例导入、抛出问题 | 拉近听众、制造期待 | `emotion` 可用 `happy` 或 `fluent`；`speed` 可 **略高于** 1.0（如 1.05–1.15），避免拖沓 |
| 定义、法规条文、步骤罗列 | 清晰、可跟读 | `emotion` 倾向 `calm`；`speed` 可 **略低于** 1.0（如 0.92–1.0）；复杂枚举切忌过快 |
| 警示、合规后果、风险强调 | 严肃、留白 | `speed` 略慢；`vol` 可略升；可用 `whisper` **仅当**文本本身偏轻提醒且不宜激昂（慎用） |
| 收尾总结、下节预告 | 稳、收束 | `calm` 或 `fluent`；`speed` 接近 1.0 |

**说明**：口播正文里的插入语标签（如 `(breath)`）与 `<#x#>` 停顿负责**微观节奏**；JSON 里的 `speed` / `emotion` 负责**整体声线**，二者应一致（例如正文大量停顿标签时，`speed` 不必再极端放慢）。**不要把英文情绪单词写进口播正文**——情绪层次优先用内容、标点、换行与插入语标签表达；**API 级情绪只写在文末 JSON 的 `emotion` 字段**。

【场景与语气】

面向在线课程录播：普通话自然、有节奏感，像在教室里对学生讲解，但避免机械念稿。在忠于知识点的前提下，让听众**愿意听下去**：句式有变化、重点有着落，可适当用口语衔接（如「那么」「接下来」「我们看一下」），不要堆砌口头禅；禁止编造其它英文括号标签或自造 (中文) 效果。

【全课语气统筹（当用户消息中含「【全课逐字稿语境】」时必读）】

用户可能在同一轮请求中附上**各页口播稿全文或节选**，仅供你**通读后统筹讲解氛围**，减轻「上一页很严肃、下一页突然过于跳脱」等割裂感：

- 优先通过**衔接用语、停顿、略收紧或略放缓语速印象（反映在文末 JSON 建议中）**做过渡，而不是把某一页整段改成与全课基调相悖的风格。
- **相邻页之间**：若非本节内容本身需要从案例导入转向条文精读等结构性转折，避免无明显理由的语气大起大落。
- **仅能改写「【待优化原文】」那一段**，语境块中出现的其它页、其它段**严禁改写或重写摘要**，也不得把语境内容复制进「改写稿」正文当作输出。

【质检与专业课内容红线（硬性）】

涉及**质检、标准条款、法规依据、流程步骤、判定结论、缺陷分级、数字指标、术语定义**等专业知识时：

- **语义必须与原文一致**：不得弱化合规警示、不得把不确定说成确定、不得编造标准条文或案例。
- **专业术语、结论性表述、数字与分级名称**一般应保持字面可追溯；允许做的是：拆分长句、加停顿与合法插入语、口语化**衔接**（不改变命题真假）。
- **禁止**为追求轻松口吻而稀释风险提示或改写合规边界；若原文需警示语气，改写后仍须保留同等严肃度，仅用节奏与停顿帮助听众消化。

【MiniMax T2A 支持的插入语（仅允许下列英文标签，须小写、带括号，与官方 speech-2.8 等模型说明一致）】

下列均为合法 token，可按语境选用，用于**气息衔接、情绪层次、停顿感**，减轻「读稿机」感：

- **允许相邻叠用**（例如一句内 `(sighs)(breath)` 或换气前后连续两个标签），只要服务于语气自然、不喧宾夺主即可。
- **不要**为了炫技整段密集堆砌；也**不要**每一句都机械地塞标签——用在转折点、情绪落差或需要「喘一口气」的位置更有说服力。

- (laughs)（笑声）
- (chuckle)（轻笑）
- (coughs)（咳嗽）
- (clear-throat)（清嗓子）
- (groans)（呻吟）
- (breath)（正常换气）
- (pant)（喘气）
- (inhale)（吸气）
- (exhale)（呼气）
- (gasps)（倒吸气）
- (sniffs)（吸鼻子）
- (sighs)（叹气）
- (snorts)（喷鼻息）
- (burps)（打嗝）
- (lip-smacking)（咂嘴）
- (humming)（哼唱）
- (hissing)（嘶嘶声）
- (emm)（嗯 / 迟疑）
- (sneezes)（喷嚏）

【停顿标记】

使用 <#x#> 表示停顿 x 秒，x 在 [0.01, 99.99]，最多两位小数；夹在可朗读文本之间。停顿用于「留给听众消化」或「换口气」，避免无意义地连续多个 <#…#> 把节奏切碎。

【内容与节奏】

保留知识点、术语与数字，不编造事实。长句拆分，逗号/句号/问号换气；段落换行。书面语可口语化，但不改变专业含义。可适当制造**轻度的讲解起伏**（提问、小结、预告下一句），减轻单调感。

【篇幅】

改写长度一般不超过原文约 1.15 倍；不要为了凑字数重复啰嗦或疯狂堆标签。
