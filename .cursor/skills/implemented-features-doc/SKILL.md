# 同步「已实现功能说明」文档

## 强制范围

凡在本仓库**新增或变更**「已实现」行为（CLI、Web、API、预览、配置、子项目 `ppt_course_rebuilder/` 等），在完成代码后**必须**同步更新 **`docs/已实现功能说明.md`**，除非用户明确只要代码不要文档。

## 文档结构（不得打乱）

1. **文首元数据表**：`| 元数据 | 内容 |` —— 含 **文档版本**、**说明对象**、**修订沿革** 指向文末。
2. **源码版本对照表**：与 `pyproject.toml` / `ppt_course/__init__.py` 一致；若 bump 了包版本，此处必须同改。
3. **正文**：按现有章节划分 —— **一、`ppt_course`**（命令行、流水线、Web 接口与界面、PNG 预览等）、**二、`ppt_course_rebuilder/`**、**三、待实现与未纳入范围**（仅写**未**实现项，不与上文已实现混写）。
4. 能力描述以 **Markdown 表格** 为主（`| 能力 | 说明 |`），与原文风格一致；新增接口/按钮/行为写入对应小节表格或列表。

## 文档修订记录（文末）— 必须遵守

规则全文以 `docs/已实现功能说明.md` 内 **「文档修订记录 → 编排规则（请先读）」** 及 **「文档维护约定」** 为准。摘要如下：

- **日期**：用三级标题 `### YYYY-MM-DD（中文日期）`；**多个日期时，较新的日期在上，较早的在下**。
- **同一天多次修改**：用四级标题 `#### 迭代 n`；**同一天内 n 越大表示越新**；**较新的迭代写在上面**；仅**当日最新**一条标题带 **`（本日最新）`**，旧迭代去掉该后缀。
- 叙述本轮改了什么（功能、文档版本、版本号核对等）；**纯措辞微调**也应记在当日某一迭代下。
- 若递增 **文档版本**（如 1.2 → 1.3），在元数据表与修订记录中一并体现。

## 执行步骤（Agent）

1. 读 `docs/已实现功能说明.md` 现有章节，定位应更新的表格或小节（Web/API/CLI/预览/子项目）。
2. 用准确、简洁的中文补充「已实现」描述；**不要**把仍属设想或未落地的内容写进已实现章节（应放在 **三、待实现与未纳入范围** 或从该表删除已落地项）。
3. 在 **文档修订记录** 顶部按规则追加日期块或迭代块，写明本次变更要点。
4. 若修改了根目录包版本，同步 **源码版本对照** 与 `pyproject.toml` / `__init__.py`。
